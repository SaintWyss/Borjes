<task type="auto" tdd="true">
  <name>Task 2: deterministic radial_layout + register module</name>
  <files>src/nav.rs, src/lib.rs, src/main.rs</files>
  <read_first>
    - src/lib.rs and src/main.rs (the module lists — add `pub mod nav;` / `mod nav;`)
    - docs/superpowers/specs/2026-06-28-neura-v3-design.md ("Layout por-carpeta: radial determinista")
  </read_first>
  <behavior>
    - radial_layout(0) returns an empty Vec.
    - radial_layout(1) returns one position on the ring (not the origin — the hub sits at origin, the lone child sits out on the ring).
    - radial_layout(n) returns n positions evenly spaced on a circle centered at the origin (angles i*2PI/n).
    - The ring radius grows with n so children do not overlap (e.g. radius = BASE + PER_CHILD * n), documented constants.
    - Pure + deterministic: same n always yields the same Vec; no RNG, no time.
  </behavior>
  <action>
    Add `pub fn radial_layout(n: usize) -> Vec<bevy::math::Vec2>` to src/nav.rs. Hub is implied at the origin (0,0) — callers place the hub there; this returns only the CHILD positions. For each i in 0..n: angle = i as f32 * std::f32::consts::TAU / n as f32; radius = `RADIAL_BASE + RADIAL_PER_CHILD * n as f32`; push `Vec2::new(angle.cos()*radius, angle.sin()*radius)`. Define `pub const RADIAL_BASE: f32` and `pub const RADIAL_PER_CHILD: f32` with values that keep ~12 children comfortably spaced (e.g. BASE 6.0, PER_CHILD 0.4) and a comment that F11 will tune them visually. Mark `#[allow(dead_code)]` (consumed by F11). Then register the module: add `pub mod nav;` to src/lib.rs and `mod nav;` to src/main.rs (alphabetical, next to `mod layout;`). Unit tests: len matches n for n in [0,1,5,12]; n==1 position magnitude ~= radius (not origin); all positions for a given n share the same magnitude (on one circle); radial_layout(5) is bit-identical across two calls (determinism).
  </action>
