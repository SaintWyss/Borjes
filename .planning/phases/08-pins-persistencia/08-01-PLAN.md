<objective>
Build the persistence + visual-asset foundation Phase 8 needs before any right-click wiring: a path-keyed pin store that reads/writes `~/.config/datatree-rs/pins.json`, and the cached gold material that marks pinned nodes. No interaction logic yet — this plan only creates the building blocks Plans 02 and 03 consume.

**Key decision (flagged, not silently assumed):** Cargo.toml currently has NO serde/serde_json, and the project has stayed lean with zero hand-added crates through Phase 7. pins.json is a flat array of absolute path strings — a trivial schema. This plan therefore hand-rolls std-only JSON for the array (option **b**: a few lines of escape/parse, zero new deps), which is the **recommended** path. Option **a** (add `serde` + `serde_json`) stays documented as the upgrade path IF pins later grow structured fields (labels, colors, order) — at which point adding those crates would need the user's explicit OK. Nothing in this plan adds a dependency.

Purpose: Establish the contracts (PinStore, load_pins, save_pins, PinAssets) so Plan 02 wires the menu and Plan 03 re-applies the gold mark without exploring the codebase or re-deciding persistence.
Output: src/pins.rs (PinStore + load/save + JSON helpers + unit tests); PinAssets + setup_pin_assets in src/render.rs; mod pins + PinStore insertion + setup_pin_assets registration in src/main.rs.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local FS → app | load_pins reads ~/.config/datatree-rs/pins.json — the app's own config file under the user's home; no network, no privilege boundary |
| app → local FS | save_pins writes the same file; the only write target is the user-owned config dir |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Denial of Service / Tampering | corrupt or oversized pins.json fed to parse_json_array | mitigate | parse_json_array returns None on any malformation → load_from yields an empty set, no panic (resilient parse) |
| T-08-02 | Tampering | a crash mid-write truncating pins.json | mitigate | save_to writes a temp file then `std::fs::rename` for an atomic publish — the live file is never partially written |
| T-08-03 | Information Disclosure / Path traversal | pinned strings interpreted as filesystem paths | accept | Paths originate only from the user's own scanned folder tree (FolderNode.path) and are only stored/compared, never executed; traversal is N/A — same trust level as the file manager |
| T-08-SC | Tampering | npm/pip/cargo installs | accept | N/A — zero new packages; std-only hand-rolled JSON was chosen specifically to avoid adding serde this phase |
</threat_model>
